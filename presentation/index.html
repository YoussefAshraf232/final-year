The problem

Inventory operations break without a controlled system

Spreadsheets and disconnected tools lose the one thing warehouses depend on: trustworthy stock.
Inventory MSManagement System

Fragmented data

Products, stock, suppliers, and sales live in separate sheets that drift out of sync.

Weak traceability

Quantities are overwritten in place — no record of who changed what, or why.

Manual transactions

Receiving, sales, returns, and transfers are handled by memory and ad-hoc edits.

No access control

Everyone can touch everything — no roles, no per-warehouse boundaries, no approvals.

Consequence: stockouts, phantom inventory, disputed numbers, and zero accountability when something goes wrong.

Challenges & engineering decisions

The hard parts — and how we resolved them

Inventory MSManagement System

Stock consistency

Transactional writes + movement ledger; receiving — not creation — adds stock (V8).

Lifecycle modeling

Explicit status columns & sub-states instead of booleans or deletes.

Warehouse scoping

Centralized access service so scope is enforced once, server-side.

Schema evolution

14 ordered Flyway migrations; back-fill scripts protect existing data.

UI ↔ server sync

React Query invalidation keeps the UI truthful after every mutation.

Traceability

Audit log + stock movements give a complete operational record.

Limitations & future work

Honest about today; clear about tomorrow

Inventory MSManagement System

Current limitations today

  • Registration flow vs. seeded roles need careful pairing before deployment.
  • Seeded admin hash must be rotated before any real use.
  • Reporting covers core metrics; advanced analytics not yet built.
  • Single-currency, single-language as implemented.

Future work proposed

  • Barcode / scanner-driven receiving and counts.
  • Reorder points with automatic purchase suggestions.
  • Richer analytics & exportable financial dashboards.
  • Refresh-token rotation & per-permission UI gating.
Limitations are stated as current; future items are explicitly proposals, not claims of completed work.
